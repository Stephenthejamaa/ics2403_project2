# Power BI Dashboard — Build Guide

This guide turns the CSVs exported by `assignment2_bigdata_extension.py`
(in `assignment2_m3_m4/results/powerbi/`) into a Power BI dashboard.

> Power BI Desktop files (`.pbix`) are a binary format created by the Power
> BI Desktop application itself — they cannot be generated by a script. This
> guide is the exact recipe to build the dashboard in a few minutes using
> Power BI Desktop's own import tools.

## Prerequisites

* Power BI Desktop installed (free, Microsoft Store or powerbi.microsoft.com)
* You have run `python -m assignment2_m3_m4.assignment2_bigdata_extension`
  at least once, so `results/powerbi/*.csv` exist

## Files you'll import

| File | What it contains |
|---|---|
| `scalability_results.csv` | Milestone 3: throughput/latency/loss vs number of edge nodes |
| `election_results.csv` | Milestone 4: Bully election outcomes (rounds, messages, consistency) |
| `architecture_services.csv` | Milestone 3: which services each node hosts |
| `speed_layer_summary.csv` | Live-platform performance on the 600-task sample |
| `speed_layer_task_log.csv` | Per-task results from the live sample (for breakdowns by node/class) |
| `../bigdata/batch_summary_by_service_class.csv` | Spark batch layer: 100,000-row dataset, aggregated by traffic class |
| `../bigdata/batch_summary_by_node.csv` | Spark batch layer: 100,000-row dataset, simulated load per node |

## Steps

1. **Open Power BI Desktop** → **Get Data** → **Text/CSV**. Import all 7
   files above one at a time (Get Data → Text/CSV → browse → Load). Do this
   for each file — you'll end up with 7 tables in the Fields pane on the right.

2. **Scalability page** — new page, rename it "Scalability (M3)":
   - Add a **Clustered Column Chart**: Axis = `n_edge_nodes`, Values =
     `packet_loss_rate` (from `scalability_results`). Shows rejection rate
     dropping as edge capacity scales out.
   - Add a **Line Chart** alongside it: Axis = `n_edge_nodes`, Values =
     `throughput_tasks_per_sec` and `mean_latency_ms` (both, as two lines).

3. **Coordination page** — new page, rename it "Coordination (M4)":
   - Add a **Table** visual using `election_results`: columns `scenario`,
     `initiator`, `elected_leader`, `rounds`, `total_messages`, `elapsed_ms`,
     `consistent_across_all_nodes`.
   - Add a **Clustered Bar Chart**: Axis = `initiator`, Values =
     `total_messages` — visually shows election message-complexity dropping
     for higher-ranked initiators.

4. **Architecture page** — new page, rename it "Architecture (M3)":
   - Add a **Table** or **Matrix** visual using `architecture_services`:
     Rows = `node_type`, then `node`, Values = `service` — shows the service
     decomposition per tier.

5. **Big Data Batch Layer page** — new page, rename it "Batch Layer — 100K rows (Spark)":
   - Add a **Pie Chart** or **Donut Chart**: Legend = `service_class`, Values
     = `task_count` (from `batch_summary_by_service_class`) — traffic-class
     composition across the full 100,000-row dataset.
   - Add a **Clustered Column Chart**: Axis = `assigned_node`, Values =
     `total_cpu_demand` and `total_bandwidth_demand_mbps` (from
     `batch_summary_by_node`) — simulated load per node at big-data scale.
   - Add a **Card** visual showing total rows processed: on the Batch Layer
     page, add a Card, and set its value to a manually-typed measure (New
     Measure → `Total Rows = SUM(batch_summary_by_service_class[task_count])`).

6. **Live Platform page** — new page, rename it "Speed Layer (Live Sample)":
   - Add a **Card** for each row of `speed_layer_summary` (throughput, mean
     latency, jitter, packet loss) — easiest way: Transform Data → pivot
     `speed_layer_summary` from long (metric/value) to wide format first
     (Home → Transform Data → select `metric` column → Transform → Pivot
     Column, using `value` as the values column), then drag each resulting
     column onto its own Card visual.
   - Add a **Stacked Bar Chart** using `speed_layer_task_log`: Axis = `node`,
     Legend = `status`, Values = Count of `status` — shows completed vs
     rejected vs dropped tasks per node.

7. **Tie the pages together**: Insert → Buttons → Blank, one per page, and
   set each button's Action → Page Navigation to jump between pages, OR just
   use the built-in page tabs at the bottom — either is fine for a group
   presentation.

8. **Save** as `5g6g_platform_dashboard.pbix` inside the project folder
   (e.g. `assignment2_m3_m4/`) so it's included when you push to GitHub
   alongside the code and the PDF reports.

## Refreshing after re-running the extension script

If you re-run `assignment2_bigdata_extension.py` (e.g. after changing the
dataset size or workload mix), the CSVs are overwritten with new numbers.
Back in Power BI Desktop: **Home → Refresh** — all visuals update
automatically without rebuilding anything, since they're wired to the file
paths, not the file contents.
